## Wrapper → Backend Architecture

When `my_wine` detects a PE32 binary, it `execvp()`s `my_wine32` — a standalone 32-bit dynamically-linked ELF (`-no-pie`). The wrapper is replaced entirely by `my_wine32` via `execvp` — no `fork()`, no `waitpid()`. `my_wine32` independently maps the PE, sets up TEB/PEB, resolves imports, and jumps to the guest entry. The PE path is passed as `argv[1]`. No IPC, no shared memory.

```
my_wine (wrapper, src/wrapper_main.c)
  ┌─────────────────────────────────────┐
  │ open(PE) → read headers             │
  │ detect PE32                         │
  │ execvp("my_wine32", [PE_path, ...]) │
  └──────────────┬──────────────────────┘
                 │  (wrapper replaced by my_wine32)
                 ▼
my_wine32 (32-bit dynamic ELF, src/loader/pe32_entry.c)
  main() (via glibc CRT):
  - setup_unix_stack / setup_stack
  - set_thread_area (FS→TEB)
  - resolve_imports + seed_bss_vars
  - pe32_run_guest.S → jump to entry
```

glibc CRT runs first (`__libc_start_main` → constructors, `environ`/`argv` setup), then calls `main()`, which performs FS→TEB setup and the rest of the PE32 bootstrap. After CRT initialization, all PE32 syscalls go through `INLINE_SYSCALL_*` macros using raw `int $0x80`.

## Key Files

| File | Role |
|------|------|
| `src/loader/pe32_entry.c` | `main()` — PE32 child entry (called by glibc CRT): maps PE, sets up TEB/PEB, wires setup calls, seeds BSS |
| `src/loader/pe32_run_guest.S` | Switches ESP to guest stack (16-byte aligned), indirect jumps to PE entry |
| `src/syscall/syscalls_inline.h` | `INLINE_SYSCALL_*` macros for raw `int $0x80`; `set_thread_area` (syscall 243) for FS→TEB; `mmap2` wrapper |
| `src/syscall/dispatcher.c` | 32-bit `dispatcher_core()` with `__ARG(n)` for 4-byte thunks and 4-byte IAT writeback |
| `src/syscall/dispatcher_entry_asm.S` | 32-bit trampoline: saves regs, switches to UNIX stack, dispatches, restores |
| `src/syscall/thunk_gen.c` | Generates 15-byte 32-bit thunks; libc calls → `INLINE_SYSCALL_*` under `MY_WINE32` |
| `src/loader/crash_handlers.c` | 32-bit handler: `REG_EIP`/`REG_ESP` signal context, cdecl SEH; TLS calls guarded |
| `src/loader/import_resolve.c` | 4-byte IAT handling for PE32; scans thunk targets for address resolution |
| `src/loader/import_table.c` | 32-bit build uses insertion sort (no `qsort`/`strcmp`); extern data→function wrappers |
| `src/loader/teb_peb.c` | TEB32/PEB32 layout; `setup_stack()` with `g_is_32bit` path; `wine_mmap` abstraction |
| `src/wrapper_main.c` | `my_wine` wrapper: reads PE headers, detects PE32 vs PE32+, `execvp` correct backend |
| `src/syscall/mmap2_asm.S` | `synct_mmap2()` — direct `int $0x80` wrapper with EBP page-offset handling |

## What Was Abandoned

**In-Process Mode-Switch (Phase 2):** The original approach tried to execute 32-bit PE code inside the 64-bit process via `ljmp`/`lcall`. Linux blocks mode-switch instructions at CPL=3 in 64-bit processes — fundamentally unfixed. Reverted.

**WoW64 Migration Study:** An in-process Wine-style WoW64 migration was assessed and **aborted**. The wrapper/backend approach is simpler and sufficient for PE32. No plans to revisit in-process mode-switching.
